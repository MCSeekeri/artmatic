# Artmatic

面向算法艺术与故障艺术的 Web 原生时间轴工具——把算法艺术和故障艺术**按音乐结构编排**起来：统一时间轴、按拍吸附、可打关键帧、确定性逐帧导出。

> 架构宪法、硬约束、ADR 与参考代码地图见 [AGENTS.md](AGENTS.md)。修改架构 / 数据模型 / 构建方式之前，先更新它。

## 当前状态：MVP（端到端精简切片）

打开即是可编排的 demo 工程（16s @120BPM，音频程序生成）：

- **底图**：Mandelbrot 缓慢推近（realtime 生成器，zoom 关键帧曲线）
- **纹理**：Rule 110 元胞自动机生长（Worker 烘焙 → R8 纹理，screen 混合）
- **局部故障**：第 5–8 小节的 slices + channel-split（adjustment layer 语义）
- **全屏调色**：echo 拖尾（ping-pong 反馈）+ 扫描线，全程

能力清单：

| 模块 | 内容 |
|---|---|
| core | 数据模型（判别联合轨道/片段）、曲线求值（linear/step/smooth/bezier + beatAnchor + impulse/follower 闭式）、拍网格（手动 BPM+offset）、三种重叠策略（reject/push/trim 可配置）、事务式撤销栈 |
| engine | WebGL2 合成管线（ping-pong + placement + 8 种混合模式）、预览尺寸解耦、确定性时钟 |
| algos | Rule 30/90/110（bake·Worker）、生命游戏（sim·固定步长+快照+seek 重放）、Mandelbrot（realtime·参数关键帧） |
| effects | channel-split / slices / pixelate / echo(feedback) / scanlines，「新增特效 = 两个文件」（defs + glsl，glob 自动配对） |
| typography | 排版片段：独立编辑页（PowerPoint 式 Ribbon，含 Contextual Tab）、多元素（文本/矢量图形/图片）、CSS 动画预设 + 手写 keyframes、对齐/分布/层级、画布内拖拽缩放旋转 + 智能参考线；文档光栅化为纹理后走普通合成链，**因此可以被特效影响** |
| timeline | Canvas2D 网格/波形、拖拽/拍吸附/切分/多轨增删、**跨轨拖拽**、**右键在鼠标位置新建**、检查器 + 关键帧打点（可锚拍） |
| exporters | FrameSink 接口 + PNG 序列（fflate zip）紧循环导出，进度/取消 |
| 音频 | 导入音频（波形 min/max 可视化）、播放与工程时间同步 |

两条容易误解的交互约定：

- **拖动期间不结算重叠策略**：拖拽中被拖片段自由跟随鼠标（允许视觉重叠，非法落点红框预告），
  松手才按 `reject / push / trim` 结算一次。否则 trim 会在拖过去的瞬间毁掉邻居，拖回来也回不去。
  例外是缩放 + reject（单边钳制、非破坏性，实时生效）。
- **工程时长与素材长度无关**：工具条上的「时长」可任意改，片段拖出末尾会自动把工程撑长；
  导入音频只是新片段的默认长度，不会被工程时长截断。

明确不做（路线图上排在后面）：BPM 自动估计（手动拍网格已可用）、video 源、Electron/ffmpeg、WebCodecs 视频导出、曲线编辑器画布。
排版的内部情形见 AGENTS.md 的 M4 与 ADR-008/009/010。

## 快速开始

```bash
# 依赖（bun 或 npm 均可；国内网络推荐 bun，快一个量级）
bun install

# 开发（纯浏览器，不需要 Electron）
bun run dev          # http://localhost:5173

# 验证三件套
bun run check        # svelte-check 类型检查
bun run test         # vitest 单元测试（纯函数）
bun run test:e2e     # Playwright E2E（自构建 + 自起 preview + 系统 Chrome）
```

E2E 用本机 Chrome（`channel: 'chrome'`），**不需要** `playwright install`。

## 快捷键

| 键 | 作用 |
|---|---|
| Space | 播放 / 暂停 |
| S | 在播放头处切分选中片段 |
| Delete / Backspace | 删除选中片段 |
| Alt + ↑ / ↓ | 选中片段上移 / 下移一轨（跳过装不下的轨道） |
| Esc | 中止正在进行的拖拽 / 关闭弹层 |
| Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y | 撤销 / 重做 |
| Ctrl + 滚轮 | 以鼠标为锚缩放时间轴 |
| Ctrl+S | 保存工程（工程文件系统未实现，M5） |

双击片段 = 打开它自己的编辑器（排版片段打开排版页），**不再切分**；标尺拖动 = scrub 播放头；拖片段可跨轨（音频片段只进音频轨）；
右键轨道 = 在鼠标位置新建片段（原生右键菜单已禁用，文本输入框除外）；
轨道行双击名字 = 重命名；`⋯` = 该轨的二级菜单（新建片段 / 重命名 / 删除）。

排版编辑页里另有一套（`S` 与 `Alt+↑↓` 在那边**故意失效**）：

| 键 | 作用 |
|---|---|
| 单击 / Shift+单击 | 选中元素 / 加选 |
| 双击文本框 | 进入文本编辑（点别处提交，一笔撤销） |
| 空白处拖动 | 框选 |
| 拖动元素 | 移动（自动吸附参考线；按住 Alt 临时关吸附） |
| 方向键 | 移动 1px（Shift ×10） |
| Ctrl+A / Esc | 全选元素 / 取消选择 |
| Space | 播放 / 暂停（驱动 CSS 动画） |

### 参数控件（数字框 drag-to-tweak）

| 操作 | 作用 |
|---|---|
| 单击数字框 | 进入文本编辑（全选，直接打字覆盖） |
| 横向拖动数字框 | 连续改值（光标是 `ew-resize`） |
| Ctrl + 拖动 | 吸附到步长整数倍 |
| Alt + 拖动 | 精细，灵敏度 ×0.1 |
| Shift + 拖动 | 粗调，灵敏度 ×10 |
| 拖动中按 Esc | 取消这次拖动，恢复原值 |
| ↑ / ↓（聚焦数字框） | 按步长增减（Shift ×10） |

> 鼠标一路拖到窗口边缘时，控件会自动进入 Pointer Lock：光标隐藏、位移不再受屏幕边界限制，
> 于是可以继续往同一个方向拖（检查器在屏幕右侧，没有这个的话很容易撞边卡住）。
> 此时按 Esc 退出并取消这次拖动。普通拖动不会触发它。

### 品牌资源

`src/assets/brand/` 下六个文件 = 三组形状 × 亮暗两版，`Brand.svelte` 按 `variant` 与当前主题取用：

| 形状 | 文件 | 用在哪 |
|---|---|---|
| 2×2 标记 | `artmatic-small-{light,dark}.svg` | 侧栏（小尺寸） |
| 3×3 标记 | `artmatic-main-{light,dark}.svg` | 「关于」里的大图 |
| 字标 | `artmatic-fonttype-{light,dark}.svg` | 顶栏 |

标记在 `size >= 44px` 时自动换成 3×3 版——20px 的位子放 3×3 会糊成一团。

> 文件名说的是**墨色**而不是目标模式：`-dark` 是深墨（配亮背景 / 亮色主题），
> `-light` 是浅墨（配暗背景 / 暗色主题）。搞反的后果是 logo 整块隐形。

┌──────────────────────────────────────────────────────────┐

├────┬────────────────────────────────────────┬────────────┤
│ 侧 │           预览（WebGL2）                │  检查器     │
│ 栏 ├────────────────────────────────────────┤  抽屉       │
│ 44 │  工具条：播放 / BPM / offset / 吸附 /   │  （可收起、 │
│ px │         时长 / 重叠策略 / 缩放           │   宽度可拖） │
│    ├────────────────────────────────────────┤            │
│    │  轨道区（同步侧栏 + Canvas 网格/波形）   │            │
├────┴────────────────────────────────────────┴────────────┤
│ 底栏：项目名 · 工具提示 · 快捷键 · FPS                       │

窄侧栏三块：LOGO / 快捷键 · 保存 · 导出 / 设置 · 明暗切换。
**这四个入口点开的是全屏 modal**（面板里以后还会继续加东西，flyout 那种两百来像素宽的
小盒子装不下）。导出入口在侧栏的导出面板里，不在工具条——工具条只放「逐帧/逐拍」的操作。

轨道行的 `⋯` 菜单是一级平铺：`+ 纯色片段` / `+ 排版片段` / `+ 特效片段` / `+ 算法片段`
（算法再展开一级列具体生成器）。右键菜单同构，位置换成鼠标点。

顶栏是**页面**级的容器：时间轴页常驻，双击排版片段会多出一个临时的排版编辑页
（可关闭）。切页不会卸载时间轴——卸载 `Preview` 的 canvas 会丢 WebGL 上下文。

### 排版编辑页

中间是画布（实时 DOM，所见即所得），右侧是图层树，顶部是 PowerPoint 式的 Ribbon：
**开始**（字体/段落/颜色/对齐/层级）、**插入**（形状/图片）、**动画**（预设/时序/自定义 CSS），
以及两个**选择到对应元素才出现**的 Contextual Tab：**图形格式**、**图片格式**。
窗口窄时面板**横向滚动**（Office 的做法），高度固定不抖动。

画布上：单击选中、Shift 加选、空白处拖动框选；拖元素移动（自动吸附参考线，按住 Alt 临时关吸附）；
八个把手缩放（Shift 保比例、Alt 从中心）、顶部圆点旋转（Shift 吸附 15°）；
**双击文本框直接编辑**，点别处即提交（一笔撤销）。方向键微调 1px，Shift 组合 10px。

几个刻意的设计：

- 画布显示的是**实时 DOM**，与真正拿去光栅化的那份 DOM 由**同一个函数**产出
  （`buildDocDom`），样式也共用同一份声明表 —— 所以「编辑器里看到的」与「导出的」
  是结构上一致的，不是靠人肉同步。右上角的「光栅预览」开关用来**验证**这一点。
- 排版内容光栅化成纹理后走普通合成链，**因此可以被特效影响**（把故障片段放在它上面即可）。
- 字体：内置 OFL 的 Inter；中文字体在「开始 → 导入字体」里自备。
  光栅化时按文档用到的字形**自动子集化**（9.5 MB 中文字体裁到 6 KB 量级），
  所以中文动画文档也不会卡。
- 「动画 → 转为图片」是逃生舱：把当前排版 1:1 烘焙成一张 PNG，片段变成普通图片源
  （省性能，也方便交给 Affinity / Cavalry 精修）。

视觉取向（Terminal-Native）：零阴影零渐变，层次只靠不同深度的纯色表面 + 1px 实线；
圆角 4/6px；纯图标按钮永远透明底、hover 只变图标色；主题色只出现在选中/激活、焦点环、
播放头、底栏数字这几处；默认亮色，设置面板里可换 4 种预置色相或填任意 hex。

## 设计 Token

唯一真源是 `src/ui/tokens.ts`（纯数据 + 纯函数），由 `src/ui/theme-apply.ts` 写成 `:root`
的自定义属性。**`app.css` 里没有 `:root` 变量块，也不该加**——时间轴是 Canvas2D 自绘，
`ctx.fillStyle` 写不了 `var(--x)`，只写 CSS 必然在 TS 侧出现一份同值的影子副本。

分层：primitive（`--p-*`）→ semantic（`--surface-*`）→ component（`--btn-*`）→
content（`--clip-*`，片段类别色，随亮暗变但**不随品牌变**）。

## 确定性（本项目的立身之本）

- 唯一时钟 `t`（帧号/fps）：预览 rAF 与导出紧循环走同一条 `renderFrame(project, t)`。
- 随机全部带种子：`withSeededRandom`（JS 侧）/ `u_seed = hash(projectSeed, instanceId, frame)`（GLSL 侧）。
- 有状态模拟（生命游戏）：固定步长 + 每 16 步快照 + seek 从最近快照重放，`seek(f) ≡ 顺序 step f 次`。
- 反馈特效（echo）：seek 清历史；导出顺序渲染所以天然确定。
- E2E 逐像素断言：同 t 同历史状态 100 次求值零差异；导出帧 vs 预览帧差在噪声级（实测 5s/150 帧 mean ≈ 1.6e-6）。
- 排版的确定性单独验证：光栅化本身走一条**不经过 GPU 的测试钩子**（`typoRasterize`），
  所以能对它做严格断言 —— 重复光栅化逐像素一致、动画真的被 seek 到 `t` 上、
  **字体子集化 vs 全量逐像素零差异**。

> ⚠️ **已知 flaky**：`determinism` / `algos` / `effects` 里凡「同一 t 多次求值逐像素一致」
> 的断言有 60–75% 失败率，且**与代码版本无关**（用 git worktree 检出改动前的提交实测同样失败）。
> 症状固定是**个别 1–2 个像素**差，怀疑是 demo 特效栈（echo 反馈 + glitch）在 GPU 侧的边界采样竞态。
> 判断一次全量 E2E 有没有回归，要看**这 5 条是不是命中**，而不是看「失败数是不是 0」。
> 复现：`for i in $(seq 1 8); do node scripts/e2e.mjs determinism; done`

> ⚠️ **已知问题（2026-10-01 实测）**：「同 t 连续求值 100 次逐像素一致」这条断言目前
> **约 60–75% 的失败率**，且与代码版本无关——用 `git worktree` 检出改动前的提交实测同样失败
> （基线 8 次通过 3、当前 8 次通过 2，统计上无差别）。症状固定为个别 1–2 个像素（差值 ~110），
> 与预览尺寸无关。怀疑是 demo 特效栈（`echo` 反馈 + `glitch`）在 GPU 侧的边界采样竞态，尚未定位。
> 复现：`for i in $(seq 1 8); do bun run test:e2e -- determinism; done`
