## 打开导出面板

左侧竖栏的**导出**。面板上三块并列：MP4、PNG 序列、GIF。

## 三种产物

| 产物 | 什么时候用 | 注意 |
| --- | --- | --- |
| **MP4**（H.264 + AAC） | 交付成片 | 有硬编时最快，体积最小 |
| **PNG 序列** | 要再进别的软件调色 / 合成 | 无损，但体积按帧数线性增长 |
| **GIF** | 发群里、贴论坛 | 有帧率和宽度上限，窄一点才不糊 |

面板会先给你一个体积估算（比如「PNG 序列 · 按当前帧约 2.72 GB」）。这个数按当前设置算，改分辨率或区间会立刻变。

## 时长与区间

导出面板上的「时长」是**帧数**，不是秒数 —— 因为真正决定导出时间的是帧数。下面的「区间」可以只导一段。

导出会按工程帧率逐帧走一遍，和播放用的是同一套时钟。

## H.264 走的是阶梯

不是「有 WebCodecs 就能编 H.264」。应用会按从高到低的档位逐个问浏览器：Main 4.0 → 3.1 → Baseline 4.0 → 3.1，第一个被接受的就用。

有一点反直觉：**机器有硬件编码器时，Baseline 档反而可能不可用**（很多平台的硬编只提供 Main / High）。所以不能假定某一档一定在，也不能因为 Baseline 不可用就认为「不支持编码」。

四档全不可用时，MP4 会退到软件编码；再不行就只给你 PNG 序列，并在面板上直接说明原因，而不是导出到一半失败。

## 为什么导出的画面和预览一样

导出不重新实现一遍渲染：它驱动的是同一个合成器，只是把「实时播放的时钟」换成了「按帧号一帧一帧地问」。

每个时域特效的权重都从帧号与节拍闭式求值，不依赖「上一帧发生过什么」。所以第 142 帧在预览里和在导出里是同一张图 —— 这一条有专门的自动化用例盯着，任何特效写坏了状态都会被抓住。

## 校对

想确认某一帧导对了，可以拿帧签名做对照：同一帧号两次求值必须得到同一个签名。这个接口对 Agent 和脚本开放，见 [agent 控制面](/api/agent/)。
