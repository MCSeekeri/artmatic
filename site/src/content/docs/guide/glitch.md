## 两种挂法

特效片段的默认身份是**调整层**：它影响合成结果，也就是它下面那些轨道的画面。此时它自己占一条轨。

也可以把它**绑到一个源片段上**。绑定之后，这条特效链只作用于那一个片段的图层，与轨道顺序无关。做「每拍一下的闪白」这类东西时用绑定：不需要为每一次闪光开一条轨。

两种模式互斥 —— 一条特效轨要么按轨道顺序影响下面，要么绑在某个片段上。

链上的多个特效按列表顺序求值，前一个的输出是后一个的输入。

## 三个「不是滤镜」的例子

| 特效 | 它实际做的事 |
| --- | --- |
| 像素排序 | 按亮度阈值把一行像素切成段，再按角度重排。阈值和角度都是参数 |
| Datamosh | 挪用运动向量，让上一帧的像素沿着位移场拖过去。它不复制像素，它改的是「怎么动」 |
| 光学流 | 估计帧间位移场，按位移重采样。和 Datamosh 的差别是位移来自估计而不是沿用 |
| 帧间残影 | 把历史帧按一条衰减曲线叠回来。衰减是曲线，不是常数 |

这些都要读历史帧或跨帧状态，所以它们对「确定性」的写法比普通特效严格 —— 见下一节。

## 时域特效为什么可复现

每个时域特效的权重都是**从帧号和节拍闭式算出来的**，不许记「上次换帧是什么时候」。一旦记了状态，seek 到第 142 帧和顺序播到第 142 帧就会得到两个不同的画面，而导出必然走顺序路径。

代价是写法上更啰嗦一点（每个参数都得能直接由 `t` 求值），换来的是：**预览里看到的那一格，就是导出后的那一格。**

反馈型特效（比如残影、反馈回路）例外地需要历史，它们的行为是「同一帧号 + 同样的历史 → 同一结果」。渲染前清一次历史，结果就是确定的。

## 参数控件的手势

| 想做的事 | 怎么做 |
| --- | --- |
| 连续改值 | 拖动数字框 |
| 吸附到步长整数倍 | `Ctrl` 拖动 |
| 精细调节（灵敏度 ×0.1） | `Alt` 拖动 |
| 粗调（灵敏度 ×10） | `Shift` 拖动 |
| 恢复原值 | `Esc` |
| 按步长增减 | `↑` / `↓`（加 `Shift` ×10） |

## 加特效

在轨道上右键，选**特效片段**，可以从一级菜单里挑常用的，也可以进「全部特效」按名字搜索。当前工程里已经用到的特效会在选择器里带上标记，方便复用同一套参数。

## 自己写一个

一个特效就是两个文件：定义（参数表、默认值、分组）和 GLSL。写进 `src/effects/` 之后它会自动出现在选择器里，和内置的没有区别。

插件里也能带特效 —— 见 [插件](/guide/install/) 那节讲的装法。
